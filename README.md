## Учебный проект с автотестами на Java по курсу "Playwright Java: Автоматизация тестирования. Полный курс"

### Тех. стек

Фреймворки: Playwright 1.60.0, JUnit 5.11.4, Mockito 5.23.0, 
БД: PostgreSQL JDBC driver 42.7.13.

Отчеты: Allure Report 2.29.0, Thymeleaf 3.1.5.RELEASE.

### Требования

Для запуска тестов необходимы: Java 25, Maven 3.9.12.
Скачивание браузеров не требуется, т.к. Playwright самостоятельно выполяняет их установку при первой сборке.

### Запуск

Локальный запуск: 
- все тесты: `mvn test`
- один тестовый класс:  `mvn test -Dtest={имя_класса}`

Запуск в CI: выполняется при каждом push, так же настроен ручной запуск всех тестов для CI и Docker в GitHub Action. 

Для определения режима браузера в базовом классе определена переменная HEADLESS, которая вычисляется методом `System.getenv("CI")` и передается при инициации браузера в LaunchOptions. Для локальных запусков - `false`, для запусков в CI - `true`. 

Из запуска в CI исключены нестабильные тесты, которые не были разработаны в процессе обучения, часть из них примеры из теоретического блока курса, часть могут запускаться только локально, часть - ожидаемо красные: ```CheckboxTest, LocalHtmlFrameTest, YandexSearchTest, WebSocketTest, ScreenShotWhenFailTest, ModernAssertionsTest, AssertionTest, ErrorAndExceptionsTest```.

### Структура проекта
В pom.xml установлен путь к папке с исходным кодом тестов: testSourceDirectory=src. Пакет tests.java, ресурсы в src/tests/resources.

Для изучения POM выделены директории:
component - повторяющиеся компоненты сайта;
pages - страницы сайта;
tests - тесты.

Директория demo_flight_booking: тесты для изучения подключения к PostgreSQL на примере учебной БД авиабилетов.

Директория my_practice_tests: тесты для самостоятельного изучения классов и методов Playwright.

Директория saucedemo: учебное портфолио для освоения POM.

### Отчеты

Отчеты формируются средствами Allure. При локальном запуске JSON-файлы с сырыми данными сохраняются в папку `target\allure-results`. 
Чтобы сформировать и просмотреть отчет необходимо выполнить команду: `mvn allure:serve`. Для сохранения отчет в корневую папку проекта в директорию `allure-reports`, необходимо выполнить `mvn allure:report`.

В CI отчет формируется в разделе артефакты. Доступен для скачивания. Для просмотра необходим запуск виртуального сервера.

Тесты, которые падают по асертам - красные.
Тесты, которые падают по другим причинам, до выполнения асерта (таймауты, неверные локаторы, url и тд) - желтые.
Тесты, у которых проставлена аннотация @Disabled - серые.
Причина падения теста открывается на той же странице при нажатии на название теста.

Дополнительно к отчетам настроено сохранение трейсинга Playwright, и скриншотов страниц и элементов. Локально они сохраняются в папки: `target\traces` и `target\screenshots`.
В CI в разделе артефактов для каждого прогона в GitHub 

### Конвенция именования методов в Page Object

#### Методы, возвращающие Locator
Называются по элементу, который отдают, без префикса get. Если элемент уточняется параметром, уточнение идёт после имени элемента.
productCardButton(String productName), cartBadge(), loginError()

#### Методы-действия
Возвращают void, называются глаголом в форме намерения пользователя.
addToCart(String productName), removeItem(String productName)

Если действие выполнимо только в определённом состоянии страницы, метод проверяет состояние сам и бросает IllegalStateException с указанием ожидаемого и фактического состояния. Тест не обязан проверять предусловие перед вызовом.

#### Методы перехода
Выполняют действие, приводящее на другую страницу, и возвращают объект этой страницы. В имени содержится название целевой страницы.
openItemPage(String productName), openCartPage()

#### Общее
Одинаковые по смыслу методы называются одинаково во всех классах страниц. Проверка: зная имя метода на одной странице, можно предсказать имя аналогичного метода на другой, не открывая её.
